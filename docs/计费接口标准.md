# AjkAPI 应用计费接口标准（v3.1）

> 适用对象：AI 应用广场上的所有插件 / 扩展 / 桌面应用 / 移动应用 / 游戏。
> 目标：所有应用（hunit、httptxt、hconvert、hcashgift 及未来任何应用、游戏）统一按本接口接入计费，后台可配置计费方式与参数，客户端无需各自实现扣费逻辑。
>
> 完整应用开发流程（注册、认证、接口、SDK、发布、验收）见 [应用开发接口文档.md](./应用开发接口文档.md)。

## 变更记录

| 版本 | 变更 |
| --- | --- |
| v3.1 | 新应用采用防亏损安全默认值；明确按量/套餐/积分包三个运营预设与五层计费参数设置法；修正总免费次数 0 为“不启用” |
| v3.0 | 两种计费组合；免费策略四层（功能免费/试用期/总免费次数/每日免费）；基础计费与 AI 大模型分离；一次性买断；客户端兑换码充值 `POST /api/billing/redeem`；积分包梯度定价（monthly/one_time） |
| v2.0 | 首版统一计费标准 |

## 1. 核心概念

| 概念 | 说明 |
| --- | --- |
| 应用（App） | 广场上的应用，有唯一 `id` 与 `slug`（应用标识）。计费配置在后台 `plugin_billing_configs` 中维护 |
| 用户（User） | AjkAPI 用户，通过 AccessToken / API Token 标识 |
| 余额（Balance） | 用户充值获得的通用额度（quota），1 quota = 1 token 等效 |
| 基础计费（Basic Billing） | 应用基础功能收费：包月（`monthly`）或一次性买断（`one_time`），可没有 |
| AI 积分包（CreditsPackage） | 大模型调用积分，包月型（`monthly`，梯度定价 9.9/19.9/299 元/月）与临时加量包（`one_time`） |
| 积分计划（CreditsPlan） | 应用专属计划（3~8 个固定模型）或通用计划（模型较多） |
| 套餐（Subscription） | 平台级套餐（次数 + token 双额度） |
| 免费策略（Free） | 四层：功能免费 / 试用期 / 总免费次数 / 每日免费 |
| 兑换码（Redemption） | 后台生成，客户端或后台兑换，充值余额/积分包/订阅 |

### 1.1 两种计费组合（v3.0 核心）

```text
组合 1：免费 + 基础计费（包月 或 一次性买断）+ AI 积分包
组合 2：免费 + AI 积分包（无基础计费）
```

- 基础计费与全部免费权益只覆盖**非 AI 基础功能**。带 `model_name` 的调用必须使用积分、限额套餐或余额；`monthly_includes_ai` 自 v3.1 起废弃并强制为 `false`。
- AI 大模型积分包一定按包月制（`package_type=monthly`），梯度定价；可随时叠加临时加量包（`one_time`，用完为止）。
- 组合由后台对应用配置，配置变更后客户端 UI 动态变化；**用户已购积分包/包月/买断必须保留**，仅不再显示。

### 1.2 计费方式优先级

后台可配置各方式开关与优先级字符串，例如 `free,plugin_monthly,credits,subscription,balance`。
默认执行顺序（`ConsumePluginBilling` 内置）：

```text
0. 非 AI 功能免费（consume 传 feature，命中 free_features）
1. 非 AI 免费试用期（trial_days 内）
2. 非 AI 总免费次数（free_total_count 内）
3. 非 AI 有效基础订阅
4. 非 AI 每日免费额度
5. AI 积分包 / 积分
6. 套餐（包月主额度 → 已购加量包 FIFO）
7. 余额
```

任一方式整体覆盖本次费用即成功；全部不足则返回 `402` 与引导文案。

### 1.3 试运营安全默认值

新应用必须从以下默认值开始，只有在利润预演与审批通过后才能修改：

| 参数 | 默认 | 说明 |
| --- | ---: | --- |
| 目标毛利率 | 35% | 正常运营目标；低于 15% 告警；低于 0% 服务端硬拒绝 |
| 合伙人 / 开发者 / 分销商 / 极客 | 各 5% | 推荐总分佣 20%；后端联合硬上限 60% 不是日常目标 |
| L1 分组倍率 | 由利润计算器生成 | 唯一推荐日常调整的全局价格杠杆，用户可见 |
| L2 折扣率 | 1.00 | 只用于审批过的客户折扣，不把全局低价写进这里 |
| L3 平台费 | 0% + 0 固定费 | 只有明确的支付/渠道附加费才配置 |
| L4 Token 消耗倍率 | 1.00 | 试运营保持 1；只在统一口径换算时修改 |
| L5 消耗系数 | 1.00 | 仅对成本确有差异的模型/应用覆盖 |
| `per_call_quota` | 1000 | 调用方未上报 token 时的防零扣费兜底 |
| `token_per_credit` | 1000 | 1 积分折算 1000 token，套餐定价需据此反算成本 |
| `monthly_includes_ai` | false（强制） | v3.1 禁止不限量 AI，大模型调用继续走积分/限额套餐/余额 |
| `auto_renew` | false | 新应用默认由用户主动开启自动续费 |
| `free_total_count` | 0 | 不启用；大于 0 才表示累计免费 N 次 |

试运营后台提供三个一键预设：

| 预设 | 扣减顺序 | 适用场景 |
| --- | --- | --- |
| 按量计费 | 余额 | 用量波动大、先验证真实成本 |
| 套餐优先 | 包月主额度 → 已购加量包（FIFO）→ 余额 | 有稳定月度配额，超额先用加量包，再按量兜底 |
| 积分优先 | AI 积分 → 余额 | 多应用共用积分或售卖积分包 |

三种预设都保留余额兜底，避免套餐或积分耗尽后服务直接中断；若业务要求“额度耗尽即停止”，应显式关闭余额并通过管理员审批。

### 1.4 五层参数怎么设置

```text
用户应付 R = 基准价 × L1 × L2 × (1 + L3%) × L4 × L5 + L3固定费
平台毛利 = R × (1 - 总分佣率) - 上游成本 - 支付费 - 退款/汇率风险准备
```

设目标毛利率为 `m`、总分佣率为 `s`、归一化总成本为 `C`，其余层乘积为 `K`，则：

```text
最低 L1 = C / ((1 - m - s) × K)
```

示例：上游与风险总成本 `C=1`，目标毛利 `m=35%`，总分佣 `s=20%`，L2/L3/L4/L5 均为默认值，则 `L1 >= 2.223`，实际可取 `2.25`。后台利润计算器应使用各渠道真实 `upstream_cost_ratio` 的加权值计算，不能用固定 1 假装成本。

操作顺序固定为：

1. 先维护渠道真实成本与模型价格。
2. 再设置四类分佣，推荐合计不超过 20%。
3. 输入 35% 目标毛利，由计算器给出 L1。
4. L2/L3/L4/L5 保持默认，只有明确业务原因才做实体级覆盖。
5. 保存前执行 dry-run；负毛利拒绝，15% 以下二次确认，配置写审计快照。

## 2. 认证方式

客户端请求携带：

```http
Authorization: <AccessToken 或 API Token（sk-xxx）>
Content-Type: application/json
```

服务间调用（智控后台等）额外支持：

```http
X-Service-Key: <billing.service_key>
```

未配置 Token 的应用应回退到"本地免费试用模式"（见 8.3）。

## 3. 接口定义

所有接口域名以 AjkAPI 部署地址为准（如 `https://ajkapi.9zos.com`）。

### 3.1 解析应用标识

```
GET /api/marketplace/apps/{slug}
```

返回 `data.app.id`，客户端用 slug 自动解析 app_id 并缓存，避免硬编码应用 ID。

### 3.2 查询额度与权益（推荐打开应用时调用一次）

```
GET /api/billing/app-quota?app_id={appId}
```

返回统一额度明细（见 4.1）。客户端据此渲染：会员状态、剩余免费次数、余额、积分、续费/充值提醒。

### 3.3 计费扣减（每次计费操作调用一次）

```
POST /api/billing/consume
```

```json
{
  "app_id": 19,
  "call_count": 1,
  "token_count": 0,
  "model_name": "",
  "feature": "",
  "request_id": "uuid"
}
```

规则：

- `call_count`：操作次数（批量/N 篇/多文件传 N）。
- `token_count`：token 消耗；传 0 时按后台配置的"1 次 = N token"折算。
- `model_name`：非空视为大模型调用（AI 调用走 AI 积分路径；空=普通功能调用走基础订阅）。
- `feature`：功能标识，命中应用 `free_features` 列表该次免费（v3.0）。
- `request_id`：幂等 ID（必填，推荐 `crypto.randomUUID()`），相同 ID 不重复扣费。
- 成功返回 200 + 本次消费结果（来源、剩余额度）。
- `source=subscription` 时额外返回 `subscription_quota_source`：`main`=只用包月主额度、`addon`=主额度已用完并自动使用加量包、`mixed`=本次跨主额度与加量包。客户端不得要求用户重复购买包月。
- 套餐内部固定顺序为“包月主额度 → 已购加量包（按购买顺序 FIFO）”；两者合计仍不足时，才继续尝试余额等下一种已启用方式。没有已购加量包时，客户端可引导购买加量包。
- 额度不足返回 402 + `requires_upgrade` / `need_recharge` 提示。

### 3.4 查询可用模型（v3.0）

```
GET /api/billing/app-models?app_id={appId}
```

返回 `default_model`、`default_multimodal_model`、`auto_select`、`models[]`（含 `model_name`/`display_name`/`coefficient`/`multimodal`）。

客户端模型选择规范：

| 模式 | 行为 |
| --- | --- |
| 默认 | 使用 `default_model`（未配置时取列表第一个） |
| 切换 | 用户在 `models` 列表中选择，本地保存偏好 |
| 多模态任务 | 含图/视频任务只允许 `multimodal=true` 的模型，或自动切到 `default_multimodal_model` |
| 自动 | `auto_select=true` 时提供「自动」选项：纯文本用默认模型，含图任务用多模态模型 |

`coefficient` 为模型消耗系数（>=1.0），UI 应展示「消耗倍率」。通配行（`*`）不暴露给客户端。

### 3.5 订购基础订阅（包月 / 一次性买断）

```
POST /api/billing/app-subscribe
```

```json
{ "app_id": 19, "mode": "monthly", "request_id": "uuid" }
```

- `mode`：`monthly`（包月，默认）/ `one_time`（一次性买断，v3.0）。
- 从用户余额一次性扣除对应价格，开通对应时长（买断永久有效）。
- 已有有效包月时幂等返回当前订阅，不重复扣费。
- 余额不足返回 402 + `need_recharge: true` + 充值链接。
- `request_id` 幂等：同一订单 ID 重复请求不重复扣费。

### 3.6 退订基础包月（到期后生效）

```
POST /api/billing/app-unsubscribe
```

```json
{ "app_id": 19 }
```

- 当前包月保留至 `end_at`，仅标记 `cancel_at_period_end=true`，到期不再自动续费，不退款。
- 重复退订幂等返回。

### 3.7 客户端兑换码充值（v3.0）

```
POST /api/billing/redeem
```

```json
{ "key": "兑换码" }
```

- 认证：`Authorization: <AccessToken 或 API Token>`（或 `X-Service-Key` 服务间，body 需带 `user_id`）。
- 支持兑换码类型：充值卡、AI 积分包、订阅、套餐加量包。
- 成功返回 `quota_added`、`balance_remaining`、`credits_remaining`；兑换后客户端刷新 `app-quota`。
- 用户可到 AjkAPI 后台钱包页购买兑换码后在客户端输入；也支持在客户端直接输入兑换码。

### 3.8 积分计划 / 积分包（购买引导）

```
GET /api/credits/plans            # 积分计划列表（公开）
GET /api/credits/plans/{id}/models # 计划可用模型
GET /api/credits/packages         # 积分包列表（含梯度包月包/加量包）
GET /api/credits/balance          # 我的积分余额（需认证）
GET /api/credits/transactions     # 积分流水（需认证）
```

客户端「购买积分」入口展示 `packages`（按 `sort_order`），购买引导到 `recharge_url` 或后台商城；积分包也可通过兑换码在客户端充值（见 3.7）。

### 4.2 扣费结果（consume 的 `data`）

`success`、`source`（free / trial / free_total / plugin_monthly / credits / subscription / balance）、
`requires_upgrade`、`need_recharge`、`recharge_url`、`message` 以及各池剩余额度。

### 4.3 HTTP 状态码约定

| 状态码 | 含义 |
| --- | --- |
| 200 | 成功（含"已订阅"幂等返回） |
| 400 | 参数错误 |
| 401 / 403 | 未认证 / 令牌失效（客户端回退本地免费模式并提示重新连接） |
| 402 | 额度不足 / 需要开通会员 / 需要充值 |
| 500 | 服务端错误（客户端提示稍后重试，不重复扣费） |

## 5. 异常情况处理规则（服务端已内置）

| 场景 | 行为 |
| --- | --- |
| 余额不足开通包月/买断 | 返回 402 + `need_recharge` + 充值链接，不创建订阅 |
| 自动续费时余额不足 | 标记续费失败并停止续费；`app-quota` 返回 `renew_failed` + `need_recharge`，应用内提醒充值 |
| 续费任务延迟 | 延迟 ≤48h 按"到期日顺延"，避免用户损失天数；超过视为中断，需要重新订阅 |
| 并发重复订阅 | 事务内行锁 + 已订阅检查，最多只扣一次费 |
| 重复请求扣费 | `request_id` 幂等，重复请求直接返回成功不重复扣 |
| 客户端断网 | 客户端回退本地免费试用额度，联网后恢复服务端额度 |
| 令牌过期 | 客户端提示重新连接，不中断本地核心功能 |
| 批量操作无会员 | 返回 `requires_upgrade`，客户端弹出开通/充值引导 |
| 后台改计费配置 | 已购积分包/包月/买断保留，仅客户端 UI 不再显示，余额可继续消费 |
| 兑换码风控命中 | 403 + 风控文案（人工审核中/拒绝），不发放积分 |

## 7. 客户端 SDK 契约（最小实现）

所有客户端（扩展 / 桌面 / 游戏）实现以下函数即可接入：

```js
async function resolveApp(settings)            // slug → app_id
async function getEntitlement(settings)        // → 统一额度明细
async function getModels(settings)             // → 可用模型列表（v3.0）
async function consume(settings, count, opts)  // → 扣费结果（opts 可带 model_name/feature）
async function subscribe(settings, mode)       // → 开通包月/买断（v3.0）
async function unsubscribe(settings)           // → 退订
async function redeem(settings, key)           // → 兑换码充值（v3.0）
```

规则：

- 打开应用时调用一次 `getEntitlement` 渲染状态；含模型选择的应用同时调用 `getModels`。
- 每次计费操作调用 `consume`，传 `request_id`；AI 调用传 `model_name`，免费功能传 `feature`。
- `consume` 返回 `requires_upgrade` 时打开会员页；返回 `need_recharge` 时打开 `recharge_url` 或弹兑换码输入框。
- 基础订阅期内非 AI 调用 `consume` 直接成功（`source=plugin_monthly`）；AI 调用扣积分。
- 积分不足时引导购买更高梯度积分包或临时加量包（`GET /api/credits/packages`）。
- 游戏接入：把"局/次/道具"映射为 `call_count`，把"体力/金币"映射为 `token_count`，其余完全复用本接口。

## 8. 接入清单

1. 应用在广场创建（获取 slug），后台配置计费组合（两种之一）、免费策略、积分计划与模型。
2. 客户端实现 7 节 SDK 契约（复制 `docs/sdk-template.js` 到 `src/ajkapi-sdk.js`）。
3. 应用内"设置"提供：AjkAPI 地址、应用标识（slug）、AccessToken。
4. 应用内提供：模型选择 UI（默认/切换/多模态/自动）+ 兑换码充值入口。
5. 发布时在应用描述中说明免费额度、基础计费价格与积分包梯度。
6. 联调：`app-quota` → `app-models` → `consume`（feature/model_name 各路径）→ 余额不足 → `app-subscribe`（monthly/one_time）→ `redeem` → 续费/退订。
