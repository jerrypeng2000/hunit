# AjkAPI 应用计费接口标准（v2.0）

> 适用对象：AI 应用广场上的所有插件 / 扩展 / 桌面应用 / 移动应用 / 游戏。
> 目标：所有应用（hunit、httptxt、hconvert、hcashgift 及未来任何应用、游戏）统一按本接口接入计费，后台可配置计费方式与参数，客户端无需各自实现扣费逻辑。

---

## 1. 核心概念

| 概念 | 说明 |
| --- | --- |
| 应用（App） | 广场上的应用，有唯一 `id` 与 `slug`（应用标识）。计费配置在后台 `plugin_billing_configs` 中维护 |
| 用户（User） | AjkAPI 用户，通过 AccessToken / API Token 标识 |
| 余额（Balance） | 用户充值获得的通用额度（quota），1 quota = 1 token 等效 |
| 积分包（Credits） | 应用专属积分包，1 积分 = N token（后台可配） |
| 套餐（Subscription） | 平台级套餐（次数 + token 双额度） |
| 免费额度（Free） | 每日免费次数，后台可配（`free_enabled` / `free_daily_quota`） |
| 余额包月（Monthly Pass） | 从用户余额按月扣费（`monthly_price_quota`），到期自动续费（`auto_renew`），退订后到期失效 |

### 1.1 计费方式优先级

后台可配置各方式开关与优先级字符串，例如 `free,plugin_monthly,credits,subscription,balance`。
默认执行顺序：

1. 有效余额包月 → 不限次，直接成功（不额外扣费）
2. 每日免费额度 → 未用完时消耗免费次数
3. 积分包 → 积分充足时扣积分
4. 套餐 → 套餐双额度充足时扣套餐
5. 余额 → 扣余额 quota

任一方式整体覆盖本次费用即成功；全部不足则返回 `402` 与引导文案。

---

## 2. 认证方式

客户端请求携带：

```http
Authorization: <AccessToken 或 API Token（sk-xxx）>
Content-Type: application/json
```

服务间调用（智控后台等）额外支持：

```http
X-Service-Key: <billing.service_key>
```

未配置 Token 的应用应回退到“本地免费试用模式”（见 8.3）。

## 3. 接口定义

所有接口域名以 AjkAPI 部署地址为准（如 `https://ajkapi.9zos.com`）。

### 3.1 解析应用标识

```
GET /api/marketplace/apps/{slug}
```

返回 `data.app.id`，客户端用 slug 自动解析 app_id 并缓存，避免硬编码应用 ID。

### 3.2 查询额度与权益（推荐打开应用时调用一次）

```
GET /api/billing/app-quota?app_id={appId}
```

返回统一额度明细（见 4.1）。客户端据此渲染：会员状态、剩余免费次数、余额、积分、续费/充值提醒。

### 3.3 计费扣减（每次计费操作调用一次）

```
POST /api/billing/consume
```

```json
{
  "app_id": 19,
  "call_count": 1,
  "token_count": 0,
  "model_name": "",
  "request_id": "uuid"
}
```

规则：

- `call_count`：操作次数（批量/N 篇/多文件传 N）。
- `token_count`：token 消耗；传 0 时按后台配置的“1 次 = N token”折算。
- `request_id`：幂等 ID（必填，推荐 `crypto.randomUUID()`），相同 ID 不重复扣费。
- 成功返回 200 + 本次消费结果（来源、剩余额度）。
- 额度不足返回 402 + `requires_upgrade` / `need_recharge` 提示。

### 3.4 订购余额包月

```
POST /api/billing/app-subscribe
```

```json
{ "app_id": 19, "request_id": "uuid" }
```

规则：

- 从用户余额一次性扣除 `monthly_price_quota`，开通 `monthly_duration_days` 天。
- 已有有效包月时幂等返回当前订阅，不重复扣费。
- 余额不足返回 402 + `need_recharge: true` + 充值链接。
- `request_id` 幂等：同一订单 ID 重复请求不重复扣费。

### 3.5 退订余额包月（下月/到期后生效）

```
POST /api/billing/app-unsubscribe
```

```json
{ "app_id": 19 }
```

规则：

- 当前包月保留至 `end_at`，仅标记 `cancel_at_period_end=true`，到期不再自动续费，不退款。
- 重复退订幂等返回。

## 4. 统一响应结构

### 4.1 额度明细（app-quota 的 `data.detail`）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `balance_enabled` | bool | 是否启用余额计费 |
| `balance_remaining` | int | 剩余余额 quota |
| `free_enabled` | bool | 是否启用每日免费 |
| `free_daily_quota` | int | 每日免费次数 |
| `free_used_today` | int | 今日已用 |
| `free_remaining_today` | int | 今日剩余 |
| `plugin_monthly_active` | bool | 是否有有效包月 |
| `plugin_monthly_start_at` | int64 | 包月开始时间（秒） |
| `plugin_monthly_end_at` | int64 | 包月到期时间（秒） |
| `plugin_monthly_cancelled` | bool | 是否已退订（到期失效） |
| `auto_renew` | bool | 是否自动续费 |
| `monthly_price_quota` | int | 包月价格（quota） |
| `monthly_price_yuan` | float | 包月价格（元，用于展示） |
| `monthly_duration_days` | int | 包月天数 |
| `renew_failed` | bool | 上次自动续费是否失败 |
| `renew_failed_at` | int64 | 续费失败时间 |
| `need_recharge` | bool | 是否提示充值（余额不足以续费/开通） |
| `recharge_url` | string | 充值页地址 |
| `credits_remaining` | int | 剩余积分（若启用积分包） |
| `call_remaining` / `token_remaining` | int | 套餐剩余（若启用套餐） |
| `local` | bool | 客户端本地回退模式 |

### 4.2 扣费结果（consume 的 `data`）

`success`、`source`（free / plugin_monthly / credits / subscription / balance）、
`requires_upgrade`、`need_recharge`、`recharge_url`、`message` 以及各池剩余额度。

### 4.3 HTTP 状态码约定

| 状态码 | 含义 |
| --- | --- |
| 200 | 成功（含“已订阅”幂等返回） |
| 400 | 参数错误 |
| 401 / 403 | 未认证 / 令牌失效（客户端回退本地免费模式并提示重新连接） |
| 402 | 额度不足 / 需要开通会员 / 需要充值 |
| 500 | 服务端错误（客户端提示稍后重试，不重复扣费） |

## 5. 异常情况处理规则（服务端已内置）

| 场景 | 行为 |
| --- | --- |
| 余额不足开通包月 | 返回 402 + `need_recharge` + 充值链接，不创建订阅 |
| 自动续费时余额不足 | 标记续费失败并停止续费；`app-quota` 返回 `renew_failed` + `need_recharge`，应用内提醒充值 |
| 续费任务延迟 | 延迟 ≤48h 按“到期日顺延”，避免用户损失天数；超过视为中断，需要重新订阅 |
| 并发重复订阅 | 事务内行锁 + 已订阅检查，最多只扣一次费 |
| 重复请求扣费 | `request_id` 幂等，重复请求直接返回成功不重复扣 |
| 客户端断网 | 客户端回退本地免费试用额度（hunit 10 次/天、httptxt 3 篇/天、hconvert 3 次），联网后恢复服务端额度 |
| 令牌过期 | 客户端提示重新连接，不中断本地核心功能 |
| 批量操作无会员 | 返回 `requires_upgrade`，客户端弹出开通/充值引导 |

## 6. 后台配置项（admin 界面可设置）

后台“插件管理 → 计费配置”维护：

| 配置项 | 说明 |
| --- | --- |
| 计费方式开关 | 余额 / 套餐 / 积分包 |
| 优先级 | 逗号分隔顺序 |
| 计费模式 | per_token / per_call |
| 免费额度开关 + 每日次数 | 免费试用策略 |
| 包月价格（元 + quota） | 展示价与实际扣费额 |
| 包月天数 | 默认 30 |
| 自动续费开关 | 到期是否从余额自动续扣 |
| 1 积分 = N token | 积分包折算 |
| 套餐 token 系数 | 套餐折算 |
| 模型消耗系数 | 按模型配置消耗倍率 |

## 7. 客户端 SDK 契约（最小实现）

所有客户端（扩展 / 桌面 / 游戏）实现以下四个函数即可接入：

```js
async function resolveApp(settings)   // slug → app_id
async function getEntitlement(settings) // → 统一额度明细
async function consume(settings, count, opts) // → 扣费结果
async function subscribe(settings)     // → 开通包月
async function unsubscribe(settings)   // → 退订
```

规则：

- 打开应用时调用一次 `getEntitlement` 渲染状态。
- 每次计费操作调用 `consume`，传 `request_id`。
- `consume` 返回 `requires_upgrade` 时打开会员页；返回 `need_recharge` 时打开 `recharge_url`。
- 包月有效期内 `consume` 直接成功（`source=plugin_monthly`）。
- 游戏接入：把“局/次/道具”映射为 `call_count`，把“体力/金币”映射为 `token_count`，其余完全复用本接口。

---

## 8. 接入清单

1. 应用在广场创建（获取 slug），后台配置计费方式与参数。
2. 客户端实现 7 节 SDK 契约。
3. 应用内“设置”提供：AjkAPI 地址、应用标识（slug）、AccessToken。
4. 发布时在应用描述中说明免费额度与包月价格。
5. 联调：`app-quota` → `consume` → 余额不足 → `app-subscribe` → 续费/退订。
