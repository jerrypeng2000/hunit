# AjkAPI 应用开发接口文档（统一标准 v3.2）

> 适用范围：AI 应用广场上的插件、浏览器扩展、桌面应用、移动应用、游戏。
> 定位：这是所有新应用开发的唯一接口标准。注册、认证、计费、模型选择、发布、验收都按本文档执行。
> 示例应用：HUnit、CleanRead 净读、HConvert、LiTong 礼通。

## 变更记录

| 版本 | 变更 |
| --- | --- |
| v3.2 | 增加 `GET /v1/capabilities` 能力协商；统一 OpenAI 兼容 Relay 的 provider 路由约束与元数据；明确多端不得猜测服务端能力、不得把网关路由字段透传上游 |
| v3.1 | 补齐 H5、桌面 App、微信小程序、Android、iOS、浏览器插件的统一接入矩阵；明确凭据存储、支付回调、离线、签名和发布要求；修正 `free_total_count=0` 为“不启用” |
| v3.0 | 计费规范 v3.0：两种计费组合（免费+基础计费+AI积分包 / 免费+AI积分包）；免费策略四层（功能免费/试用期/总免费次数/每日免费）；基础计费与 AI 大模型分离；客户端模型选择（默认/切换/多模态/自动）；客户端兑换码充值 `POST /api/billing/redeem`；积分包梯度定价（包月型 monthly / 加量包 one_time）；应用专属积分计划与通用积分计划 |
| v2.0 | 首版统一标准：统一客户端契约、余额包月、每日免费、幂等、发布流程 |

## 1. 标准目标与治理

### 1.1 目标

- 一个应用只实现一套客户端契约，即可接入广场、额度、计费与模型选择。
- 计费方式、价格、免费额度、可用模型全部在 AjkAPI 后台配置，客户端不写死金额。
- 所有异常（重复扣费、并发、余额不足、续费失败、断网）由服务端和参考 SDK 统一处理。
- 应用本身不再自行开发计费/注册/认证类接口，一律接入 AjkAPI 通用接口。

### 1.2 版本策略

- 本文档主版本 `v3`。破坏性变更升级主版本；新增可选字段保持向后兼容。
- 客户端必须以 `request_id` 实现幂等，并对未知响应字段保持宽容。
- 服务端接口遵循「只增不改」：新增字段不动旧字段语义。

### 1.3 新应用脚手架

每次新建应用必须复制标准文档到应用目录。仓库提供脚手架：

```bash
python D:/project/ajkapi/tools/new_app.py --slug your-app --name "你的应用"
```

脚手架会自动生成并复制：

```text
your-app/
  README.md
  .gitignore
  docs/
    应用开发接口文档.md
    计费接口标准.md
  src/
    ajkapi-sdk.js
  release/
  scripts/
```

不要手写一遍又一遍的计费逻辑；复制并复用 `src/ajkapi-sdk.js`。

## 2. 应用生命周期

```text
创建应用 -> 配置计费 -> 配置模型 -> 客户端开发 -> 提交审核 -> 上架 -> 发版 -> 运营/下架
```

| 阶段 | 操作 | 结果 |
| --- | --- | --- |
| 创建 | 后台创建应用，生成唯一 `slug` | 未上架 |
| 配置计费 | 配置免费策略、基础计费、AI 积分包、积分计划 | 计费生效 |
| 配置模型 | 配置模型系数、默认模型、多模态模型 | 模型选择生效 |
| 开发 | 按本文档实现 SDK | 可联调 |
| 审核 | 管理员审核应用与定价 | `review_status=approved` |
| 上架 | 设置 `enabled=true`，填写图标/截图/下载地址 | 广场可见 |
| 发版 | 更新 `version`、`changelog`、`runtime_config` | 用户可下载 |
| 运营 | 监控额度接口与续费任务 | 持续稳定 |

## 3. 认证与授权

### 3.1 应用客户端

应用内使用用户令牌：

```http
Authorization: <AccessToken 或 API Token（sk-xxx）>
Content-Type: application/json
```

规则：

- 令牌由用户在 AjkAPI 控制台获取，在应用「设置」里填写。
- 令牌无效返回 `401`/`403`，客户端回退本地免费模式并提示重新连接。
- 应用客户端只访问计费接口，不访问广场安装/评价等 Web 接口。

### 3.2 服务间调用

智控后台、运维脚本使用：

```http
X-Service-Key: <billing.service_key>
```

### 3.3 管理后台

管理接口需要管理员会话：

- 登录后携带 `Ajk-Api-User: <uid>`。
- 写操作携带 CSRF Token。

## 4. 通用约定

### 4.1 基础地址

- 生产：`https://ajkapi.9zos.com`
- 所有接口前缀：`/api`

### 4.2 响应包络

```json
{
  "success": true,
  "message": "",
  "data": {}
}
```

- 业务成功但无数据时 `data` 可为 `null` 或空对象。
- 业务失败时 `success=false`，`message` 提供用户可读文案。

### 4.3 分页

列表接口统一使用：

```text
p=1&page_size=20
```

响应含 `total`、`page`、`page_size`。

### 4.4 时间与金额

- 时间戳为 Unix 秒（`int64`）。
- `quota` 为平台额度单位；`yuan` 为人民币展示价，两者分别维护。

### 4.5 幂等

- 扣费与订购必须携带 `request_id`。
- 相同 `request_id` 只生效一次，重复请求直接返回成功。
- 客户端使用 `crypto.randomUUID()` 生成。

### 4.6 错误码

| HTTP | 含义 | 客户端行为 |
| --- | --- | --- |
| 200 | 成功（含幂等返回） | 继续 |
| 400 | 参数错误 | 提示错误 |
| 401 / 403 | 未认证 / 令牌失效 / 越权 | 回退本地免费模式，提示重新连接 |
| 402 | 额度不足 / 需要开通 / 需要充值 | 打开会员页或充值页 |
| 500 | 服务端错误 | 提示稍后重试，不重复扣费 |

### 4.7 能力协商（v3.2 必须）

所有 H5、桌面 App、微信小程序、Android、iOS 和浏览器插件在连接新部署时必须读取：

```http
GET /v1/capabilities
```

该接口不返回秘密，可缓存 5 分钟。客户端按 `schema_version` 与 `routing`、`billing`、`guardrails` 声明启用功能；未知字段忽略，缺失能力自动隐藏，禁止根据域名或版本字符串猜测。

关键校验：

- `billing.funding_order` 必须是 `monthly_quota → addon_pack → wallet_balance`。
- SDK 若使用请求级路由，先确认 `routing.request_field=provider`。
- 私有化/OEM 版本也必须实现同一能力接口，不能让客户版形成另一套客户端协议。

### 4.8 AI Relay 路由扩展（可选）

OpenAI 兼容请求可增加 `provider`，它只会收窄 Token 已有权限：

```json
{
  "model": "gpt-example",
  "messages": [{"role": "user", "content": "hello"}],
  "provider": {
    "only": ["openai", "azure"],
    "allow_fallbacks": true,
    "require_parameters": true,
    "data_collection": "deny",
    "sort": "latency",
    "max_latency_ms": 2500,
    "max_upstream_cost_ratio": 0.85
  }
}
```

调试时增加 `X-AjkAPI-Routing-Metadata: true`，读取 `X-AjkAPI-Route-Provider/Attempt/Strategy/Fallback/Group`。默认不返回路由元数据；任何模式都不暴露渠道 Key、Base URL、内部渠道 ID 或真实成本。

机器规范：`docs/schemas/ajkapi-provider-routing.schema.json`；设计与安全语义：`docs/OPENROUTER_OPENCODE_DESIGN.md`。

## 5. 广场公开接口

这些接口供广场列表、详情页和客户端自动解析 `slug` 使用。

### 5.1 应用列表

```http
GET /api/marketplace/apps?p=1&page_size=20&category=code&tag=llm&sort=popular
```

参数：

| 参数 | 说明 |
| --- | --- |
| `category` | 分类 |
| `tag` | 标签 |
| `sort` | `popular`(默认) / `newest` / `rating` / `downloads` / `name` |
| `keyword` | 关键词 |
| `plugin_type` | 插件类型，如 `tool` / `mcp_server` |
| `min_rating` | 最低评分 |

响应：`data.items`、`data.total`、`data.page`、`data.page_size`。

### 5.2 应用详情

```http
GET /api/marketplace/apps/{slug}
```

响应：

```json
{
  "data": {
    "app": {},
    "versions": [],
    "pricing": {}
  }
}
```

客户端用 `data.app.id` 自动解析 `app_id`，并缓存到本地设置。

### 5.3 分类与定价

```http
GET /api/marketplace/categories
GET /api/marketplace/apps/{id}/pricing
```

### 5.4 评价列表

```http
GET /api/marketplace/apps/{id}/ratings?p=1&page_size=10
```

响应含 `items`、`total`、`distribution`。

## 7. 计费模式规范（v3.0 核心）

### 7.1 两种计费组合

所有应用的计费组合只允许以下两种，由后台配置（`basic_billing_type` 等字段）：

```text
组合 1：免费 + 基础计费（包月 或 一次性买断）+ AI 积分包
组合 2：免费 + AI 积分包（无基础计费）
```

- 基础计费、免费功能、试用期和免费次数只覆盖**非 AI 基础功能**。只要请求携带 `model_name`，就必须进入积分、限额套餐或余额扣费链路。
- `monthly_includes_ai` 自 v3.1 起废弃并强制为 `false`；存量 `true` 不再产生不限量 AI 权益，下一次保存配置时自动迁移。
- 基础计费不一定要有（组合 2 即无基础计费）；但 AI 大模型积分包一定是包月制（`package_type=monthly`），另有临时加量包（`package_type=one_time`）。
- 包月额度用完后使用临时加量包，不要求用户重复购买包月；加量包一次性补充、用完为止，下个计费周期仍先使用新发放的包月额度。

### 7.2 免费策略（四层，按优先级命中即免费）

| 优先级 | 策略 | 配置 | consume 行为 |
| --- | --- | --- | --- |
| 0 | 功能免费 | `free_features`（JSON 数组，功能标识） | 非 AI 请求带 `feature` 命中列表即永久免费 |
| 1 | 免费试用期 | `trial_days`（自首次调用起 N 天） | 非 AI 基础功能在试用期内免费 |
| 2 | 总免费次数 | `free_total_count`（累计 N 次，0=不启用） | 非 AI 基础功能未达上限免费 |
| 3 | 每日免费次数 | `free_enabled` + `free_daily_quota` | 非 AI 基础功能在当日剩余次数内免费 |

执行顺序（服务端 `ConsumePluginBilling` 内置）：非 AI 免费权益/基础订阅 → 积分包 → 限额套餐（包月主额度 → 已购加量包 FIFO）→ 余额。AI 调用跳过全部免费权益与固定价基础订阅。

### 7.3 基础计费

| 类型 | 配置 | 行为 |
| --- | --- | --- |
| 基础包月 | `basic_billing_type=monthly`、`monthly_price_quota`/`monthly_price_yuan`、`monthly_duration_days`、`auto_renew` | 余额扣费开通；到期自动续费（可关）；退订到期生效 |
| 一次性买断 | `basic_billing_type=one_time`、`one_time_price_quota`/`one_time_price_yuan` | 余额扣费一次，永久有效，不自动续费 |

### 7.4 AI 积分包（CreditsPackage）

| 字段 | 说明 |
| --- | --- |
| `package_type=monthly` | AI 积分包（包月型），梯度定价（如 9.9 / 19.9 / 299 元/月） |
| `package_type=one_time` | 临时加量包（一次性补充，用完为止） |
| `plan_id` | 关联积分计划；0=通用包（可抵扣所有计划） |
| `plugin_id` | 0=共享包；>0=应用专属包 |
| `credits` | 积分数量；`token_per_credit` 决定 1 积分=N token |

### 7.5 积分计划：应用专属 vs 通用

- **应用专属积分计划**：应用在后台绑定自己的积分计划（`credits_plan_id`），并挑选少量固定大模型（建议 3~8 个，太多用户会晕）。计费模型列表由应用级模型系数配置。
- **通用积分计划**：所有应用可用，大模型较多，适合不想维护模型列表的应用。
- 应用只能使用后台 `allowed_credits_plan_ids` 允许的计划（空=不限）。

### 7.6 配置变更与已购权益保留

后台修改应用计费配置（如关闭基础包月、更换积分计划）后：

- 客户端 UI 随配置动态变化（不再显示已关闭的计费方式）。
- 用户**之前购买的积分包/包月/买断必须保留**，只是客户端不再显示，余额仍可消费直至用完/到期。

## 8. 应用客户端计费接口

应用客户端只需对接以下接口（前 6 个为最小集合）。

### 8.1 查询额度

```http
GET /api/billing/app-quota?app_id={appId}
```

响应 `data.detail` 字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `balance_remaining` | int | 剩余余额 quota |
| `free_enabled` / `free_daily_quota` | bool/int | 每日免费开关与次数 |
| `free_used_today` / `free_remaining_today` | int | 今日已用/剩余 |
| `plugin_monthly_active` | bool | 是否有有效基础订阅（包月/买断） |
| `plugin_monthly_start_at` / `plugin_monthly_end_at` | int64 | 订阅起止时间 |
| `plugin_monthly_cancelled` | bool | 是否已退订（到期失效） |
| `auto_renew` | bool | 是否自动续费 |
| `monthly_price_quota` / `monthly_price_yuan` | int/float | 包月价格（quota / 元） |
| `monthly_duration_days` | int | 包月天数 |
| `renew_failed` / `renew_failed_at` | bool/int64 | 上次自动续费是否失败 |
| `need_recharge` | bool | 余额不足，需要充值 |
| `recharge_url` | string | 充值页地址 |
| `credits_remaining` | int | 剩余积分 |
| `call_remaining` / `token_remaining` | int | 套餐剩余 |
| `basic_billing_type` | string | 基础计费类型：''（无）/ `monthly` / `one_time`（v3.0） |
| `monthly_includes_ai` | bool | v3.1 废弃字段，服务端固定返回 `false` |
| `one_time_price_quota` / `one_time_price_yuan` | int/float | 一次性买断价格（v3.0） |
| `trial_days` / `trial_end_at` | int/int64 | 试用期天数/到期时间（v3.0） |
| `free_total_count` / `free_total_used` / `free_total_remaining` | int | 总免费次数；0 表示不启用，remaining 最小为 0 |
| `free_features` | []string | 永久免费功能列表（v3.0） |
| `default_model` / `default_multimodal_model` | string | 默认模型/默认多模态模型（v3.0） |
| `local` | bool | 客户端本地回退模式 |

### 8.2 计费扣减

```http
POST /api/billing/consume
```

请求：

```json
{
  "app_id": 19,
  "call_count": 1,
  "token_count": 0,
  "model_name": "",
  "feature": "",
  "request_id": "uuid"
}
```

规则：

- `call_count`：操作次数；`token_count`：token 消耗，为 0 时按后台「1 次=N token」折算。
- `model_name`：非空视为大模型调用（AI 调用走 AI 积分路径；空=普通功能调用走基础订阅）。
- `feature`：功能标识，命中 `free_features` 列表即该次免费（v3.0）。
- 套餐内部固定按“包月主额度 → 已购加量包（FIFO）”扣减；合计仍不足时才进入余额兜底。`source=subscription` 时，读取 `subscription_quota_source`（`main` / `addon` / `mixed`）展示实际扣费来源。
- 成功 200；额度不足 402（`requires_upgrade`/`need_recharge` 引导）。

### 8.3 查询可用模型（模型选择，v3.0）

```http
GET /api/billing/app-models?app_id={appId}
```

响应：

```json
{
  "data": {
    "app_id": 19,
    "default_model": "deepseek-chat",
    "default_multimodal_model": "gpt-4o-mini",
    "auto_select": true,
    "models": [
      {
        "model_name": "deepseek-chat",
        "display_name": "DeepSeek Chat",
        "description": "性价比之选",
        "coefficient": 1.0,
        "multimodal": false,
        "is_default": true
      }
    ]
  }
}
```

客户端模型选择 UI 规范：

| 模式 | 行为 |
| --- | --- |
| 默认 | 使用 `default_model`（未配置时取列表第一个） |
| 切换 | 用户在 `models` 列表中选择，客户端本地保存偏好 |
| 多模态任务 | 含图/视频任务只允许选 `multimodal=true` 的模型，或自动切换到 `default_multimodal_model` |
| 自动 | `auto_select=true` 时客户端可提供「自动」选项：纯文本用 `default_model`，含图任务用 `default_multimodal_model` |

- `coefficient` 为模型消耗系数（>=1.0，越高消耗越多积分），UI 应展示「消耗倍率」提示。
- 通配行（`*`）不暴露给客户端。

### 8.4 订购基础订阅（包月/买断）

```http
POST /api/billing/app-subscribe
```

```json
{ "app_id": 19, "mode": "monthly", "request_id": "uuid" }
```

- `mode`：`monthly`（默认，包月）/ `one_time`（一次性买断，v3.0）。
- 从余额扣除对应价格，开通对应时长。已有有效包月时幂等返回。
- 余额不足返回 402 + `need_recharge` + `recharge_url`。

### 8.5 退订基础包月

```http
POST /api/billing/app-unsubscribe
```

```json
{ "app_id": 19 }
```

到期后生效，不退款；当前包月保留至到期日。

### 8.6 客户端兑换码充值（v3.0）

```http
POST /api/billing/redeem
```

```json
{ "key": "兑换码" }
```

- 认证：`Authorization: <AccessToken 或 API Token>`（或 `X-Service-Key` 服务间，body 需带 `user_id`）。
- 兑换码类型支持：充值卡、AI 积分包、订阅、套餐加量包（与后台生成的兑换码一致）。
- 成功返回：

```json
{
  "data": {
    "quota_added": 500000,
    "balance_remaining": 800000,
    "credits_remaining": 1200
  }
}
```

- 客户端兑换成功后应刷新 `app-quota`。后台购买兑换码充值：用户也可到 AjkAPI 后台钱包页购买兑换码后在客户端输入。

### 8.7 积分计划/积分包（购买引导）

```http
GET /api/credits/plans          # 积分计划列表（公开）
GET /api/credits/plans/{id}/models  # 计划可用模型
GET /api/credits/packages       # 积分包列表（公开，含梯度包月包/加量包）
GET /api/credits/balance        # 我的积分余额（需认证）
GET /api/credits/transactions   # 积分流水（需认证）
```

客户端在「购买积分」入口展示 `packages`（按 `sort_order`），购买引导到 `recharge_url` 或后台商城；积分包也可通过兑换码在客户端充值（见 8.6）。

### 8.8 续费检查（运维/服务间）

```http
POST /api/billing/plugin-renew-check
```

认证：`X-Service-Key`。返回 `renewed`、`stopped`。

## 10. 计费模型与规则

### 10.1 计费方式优先级

```text
0. 非 AI 功能免费（feature 命中 free_features）
1. 非 AI 免费试用期（trial_days 内）
2. 非 AI 总免费次数（free_total_count 内）
3. 非 AI 有效基础订阅
4. 非 AI 每日免费额度
5. AI 积分包 / 积分
6. 套餐（包月主额度 → 已购加量包 FIFO）
7. 余额
```

任一方式整体覆盖本次费用即成功；全部不足返回 402。

### 10.2 token 计费层（per_token 模式）

```text
最终token = 原始token × L1分组倍率 × L2折扣率 × (1+L3平台费%) × L4消费比率 × L5模型系数 + L3固定费
```

`per_call` 模式跳过 L1-L5，`per_call_quota` 即最终扣减量。AI 调用（`model_name` 非空）扣积分时按 `token_per_credit` 折算积分。

### 10.3 异常处理（服务端内置）

| 场景 | 行为 |
| --- | --- |
| 余额不足开通包月/买断 | 402 + `need_recharge` + 充值链接 |
| 自动续费余额不足 | 停止续费 + `renew_failed` + 应用内提醒充值 |
| 续费任务延迟 | <=48h 按原到期日顺延；超过视为中断需重新订阅 |
| 并发重复订阅 | 事务内用户行锁，最多扣一次 |
| 重复扣费请求 | `request_id` 幂等 |
| 断网 | 客户端回退本地免费额度 |
| 后台改配置 | 已购积分包/订阅保留，仅 UI 不再显示 |

## 11. 客户端 SDK 契约与参考实现

### 11.1 契约

```js
resolveApp(settings)          // slug -> app_id，自动解析并缓存
getEntitlement(settings)      // -> 统一额度明细
getModels(settings)           // -> 可用模型列表（默认/切换/多模态/自动）(v3.0)
consume(settings, count, opts) // -> 扣费结果（opts 可带 model_name/feature）(v3.0)
subscribe(settings, mode)     // -> 开通包月/买断（mode: monthly/one_time）(v3.0)
unsubscribe(settings)         // -> 退订
redeem(settings, key)         // -> 兑换码充值 (v3.0)
```

### 11.2 参考实现

参考实现见 [sdk-template.js](./sdk-template.js)。新应用直接复制到 `src/ajkapi-sdk.js` 使用。

### 11.3 行为要求

- 打开应用调用一次 `getEntitlement`；含模型选择的应用同时调用 `getModels`。
- 每次计费操作调用 `consume`，传 `request_id`；AI 调用传 `model_name`，免费功能传 `feature`。
- `requires_upgrade` -> 会员页；`need_recharge` -> 打开 `recharge_url` 或弹兑换码输入框。
- 基础订阅期内非 AI 调用 `consume` 直接成功；AI 调用扣积分。
- 积分不足时引导购买更高梯度积分包或临时加量包（`GET /api/credits/packages`）。
- 未连接时使用本地免费额度。

### 11.4 游戏映射

- 局 / 次 / 关卡 -> `call_count`
- 体力 / 金币 / 道具 -> `token_count`
- 月卡 / 赛季通行证 -> `app-subscribe`（`mode=monthly`）
- 终身卡 -> `app-subscribe`（`mode=one_time`）
- AI 对手 / AI 剧情 -> `model_name`（走 AI 积分）

## 12. 各类客户端接入要点

所有客户端共享同一业务契约：`resolveApp → getEntitlement/getModels → consume → subscribe/redeem`。平台差异只能存在于认证凭据保存、网络代理、支付唤起与发布签名层，禁止各端自行复制一套计费规则。

| 客户端 | 认证与凭据 | 网络与计费 | 发布硬门槛 |
| --- | --- | --- | --- |
| H5 / Web | 推荐使用同域 BFF + HttpOnly/Secure/SameSite Cookie；禁止把服务密钥或长期用户 Token 放进打包代码、URL、日志 | BFF 代调平台接口；CORS 只放行登记域名；支付结果以服务端回调为准，前端轮询订单状态 | HTTPS、CSP、SRI、依赖漏洞扫描、移动端响应式与 WCAG 2.1 AA |
| 桌面 App（Electron/Tauri） | Token 存系统凭据库（Windows Credential Manager / macOS Keychain / Secret Service），渲染进程不得持有服务密钥 | 主进程统一代理；断网请求只允许进入本地待处理队列，恢复网络后携带原 `request_id` 重试 | 安装包代码签名、自动更新签名校验、SHA-256、崩溃回滚 |
| 微信小程序 | `wx.login` code 只发送到自有后端换取会话；不得把 AjkAPI 服务密钥放在小程序包或云函数日志 | 请求域名、下载域名预先加入微信白名单；支付以商户服务端通知为准；订阅/兑换成功后刷新 `app-quota` | 备案 HTTPS 域名、隐私协议、用户信息最小化、真机弱网测试、微信审核通过 |
| Android App | 用户 Token 存 Android Keystore 包装后的加密存储；禁止明文 SharedPreferences | Network Security Config 禁止生产明文 HTTP；OkHttp 拦截器统一添加请求 ID；应用内购必须服务端验签并映射平台订单 | AAB/APK 签名、ProGuard/R8、Play Integrity 或等价完整性校验、目标 SDK 合规 |
| iOS App | Token 存 Keychain；启用 ATS；服务密钥不得下发 | StoreKit 交易服务端验签；恢复购买必须幂等；后台任务复用原 `request_id` | App 签名、公证/商店审核、隐私清单、崩溃与弱网测试 |
| 浏览器插件 MV3 | 网络调用由 Service Worker 发起；短期 Token 优先 `chrome.storage.session`，持久 Token 需用户显式授权且不得同步到云端 | `host_permissions` 仅声明平台域名；Service Worker 重启后恢复未完成请求，复用原 `request_id` | 最小权限、CSP、禁止远程代码、商店包签名、Chrome/Edge 双端验收 |

共同强制项：

- 客户端只保存用户级凭据，`X-Service-Key` 只允许在受控服务端使用。
- 所有扣费、订购、兑换、恢复购买操作必须有幂等 ID；客户端超时不能生成新 ID 盲目重试。
- 客户端不计算最终价格，只展示 `app-quota`、`app-models` 和服务端订单返回的数据。
- 日志、埋点、崩溃报告必须脱敏 Authorization、Cookie、兑换码、支付凭据和用户输入。
- 每端至少验证 401、402、409/幂等、429、5xx、超时、断网恢复、重复回调和版本降级。

## 13. 发布规范

### 13.1 混淆与源码保护

- 前端/扩展发布前必须混淆：esbuild + javascript-obfuscator。
- **源代码不能公开**：Gitee/GitHub 仓库均为私有，只公开打包好的程序供用户下载。

### 13.2 发布包

| 包 | 内容 |
| --- | --- |
| `{app}-v{version}-chromium.zip` | 构建产物 + manifest + icons（混淆后） |
| `SHA256SUMS.txt` | 校验和 |

源码包仅内部存档，不对用户发布。

### 13.3 双仓库与 Release

- Gitee 私有仓库：源码 + `release/` 打包产物。
- GitHub 私有仓库：源码 + Release 资产（打包程序）。
- 广场 `runtime_config`：
  - `download_url_gitee`
  - `download_url_github`

用户通过广场下载接口获取打包程序，无法访问源码仓库。

### 13.4 广场图片（强制）

- `icon`：列表缩略图 1 张，640×360 左右，<50KB。
- `screenshots`：详情页**至少 3 张**，同尺寸规格。不足 3 张不予上架。

## 15. 安全与运营

- 令牌不写死、不进 Git；通过环境变量或本地存储注入。
- 客户端对 `recharge_url` 使用 `window.open` 前校验为 `http(s)` 地址。
- 服务端记录消费流水；`request_id` 全局幂等；兑换码兑换有风控与频控。
- 续费任务每 10 分钟运行；失败会落库供对账。
- 管理员配置系数与价格时受盈利保护校验（系数 >=1.0）。
