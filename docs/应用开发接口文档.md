# AjkAPI 应用开发接口文档（统一标准 v2.0）

> 适用范围：AI 应用广场上的所有插件、浏览器扩展、桌面应用、移动应用、游戏。
> 目标：任何新应用/游戏按本文档即可接入，无需单独设计计费；后台可配置计费方式与参数。
> 示例应用：HUnit（浏览器扩展）、CleanRead 净读（浏览器扩展）、HConvert（桌面 Web）、LiTong 礼通（Electron 桌面端）。

---

## 1. 应用接入总流程

```text
1. 注册应用（获得唯一 slug，如 hunit / hconvert）
2. 后台配置计费（免费额度、包月价格、自动续费等）
3. 客户端实现 SDK 四个函数（见 §7）
4. 真实 UI 测试（连接、扣费、开通、退订、余额不足、断网）
5. 构建并混淆代码
6. 发布到 Gitee / GitHub，上传发布包
7. 更新应用广场：版本号、更新日志、下载地址、图标与截图
8. 上线后监控额度接口与续费任务
```

## 2. 应用注册与上架规范

### 2.1 应用记录（apps 表）

| 字段 | 说明 | 示例 |
| --- | --- | --- |
| `slug` | 全局唯一应用标识，客户端用它自动解析应用 ID | `hunit` |
| `name` | 应用名称 | `换算通HUnit` |
| `description` | 功能 + 免费额度 + 包月价格 | 免费 10 次/天，2 元/月 |
| `icon` | 列表缩略图（640×360 左右，<50KB，控制流量） | `https://ajkapi.9zos.com/images/hunit-1-dim.jpg` |
| `screenshots` | 详情页截图数组，**至少 3 张** | 4 张 JSON 数组 |
| `version` | 当前版本号 | `1.2.0` |
| `changelog` | 更新日志 | Markdown |
| `runtime_config` | 下载地址 JSON（Gitee/GitHub） | 见 §9 |
| `review_status` | `approved` 后广场可见 | `approved` |

### 2.2 图片规范

- 尺寸：640×360 横图，压缩后单张 ≤50KB。
- 数量：列表缩略图 1 张（`icon`）+ 详情页 3~4 张（`screenshots`）。
- 走同源 `/images/` 路径（不强制下载附件头），浏览器可立即加载。

## 3. 认证方式

### 3.1 客户端（应用内）

```http
Authorization: <AccessToken 或 API Token（sk-xxx）>
Content-Type: application/json
```

- AccessToken 由用户在 AjkAPI 控制台获取，在应用“设置”里填入。
- 令牌无效返回 401/403，客户端应回退本地免费模式并提示重新连接。

### 3.2 服务间（智控后台 / 运维脚本）

```http
X-Service-Key: <billing.service_key>
```

### 3.3 管理后台

登录后请求需带 `Ajk-Api-User: <uid>` 头；写操作带 CSRF Token。

## 4. 接口总览

| 接口 | 方法 | 认证 | 说明 |
| --- | --- | --- | --- |
| `/api/marketplace/apps/{slug}` | GET | 无 | 按应用标识解析应用（拿到 app_id） |
| `/api/billing/app-quota?app_id=N` | GET | 用户 | 查询统一额度与权益 |
| `/api/billing/consume` | POST | 用户/服务间 | 计费扣减（幂等） |
| `/api/billing/app-subscribe` | POST | 用户/服务间 | 余额包月订购（幂等） |
| `/api/billing/app-unsubscribe` | POST | 用户/服务间 | 退订（下月生效） |
| `/api/billing/plugin-renew-check` | POST | 服务间 | 手动触发续费检查（运维） |
| `/api/admin/plugins/:id/billing/config` | GET/PUT | 管理 | 读取/修改计费配置 |
| `/api/admin/plugins/billing/renew-check` | POST | 管理 | 手动触发续费检查（后台） |

## 5. 统一响应结构

### 5.1 额度明细（`app-quota` 的 `data.detail`）

客户端打开应用时调用一次，用于渲染会员状态与充值提醒。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `balance_remaining` | int | 剩余余额 quota |
| `free_enabled` / `free_daily_quota` | bool/int | 每日免费开关与次数 |
| `free_used_today` / `free_remaining_today` | int | 今日已用/剩余 |
| `plugin_monthly_active` | bool | 是否有有效包月 |
| `plugin_monthly_start_at` / `plugin_monthly_end_at` | int64 | 包月起止时间 |
| `plugin_monthly_cancelled` | bool | 是否已退订（到期失效） |
| `auto_renew` | bool | 是否自动续费 |
| `monthly_price_quota` / `monthly_price_yuan` | int/float | 包月价格（quota / 元） |
| `monthly_duration_days` | int | 包月天数 |
| `renew_failed` / `renew_failed_at` | bool/int64 | 上次自动续费是否失败 |
| `need_recharge` | bool | 余额不足，需要充值 |
| `recharge_url` | string | 充值页地址（如 `/wallet`） |
| `credits_remaining` | int | 剩余积分（启用积分包时） |
| `call_remaining` / `token_remaining` | int | 套餐剩余（启用套餐时） |
| `local` | bool | 客户端本地回退模式 |

### 5.2 扣费结果（`consume` 的 `data`）

`success`、`source`（free / plugin_monthly / credits / subscription / balance）、
`requires_upgrade`、`need_recharge`、`recharge_url`、`message` 及各池剩余额度。

### 5.3 HTTP 状态码

| 状态码 | 含义 | 客户端行为 |
| --- | --- | --- |
| 200 | 成功（含幂等返回） | 继续 |
| 400 | 参数错误 | 提示错误 |
| 401 / 403 | 未认证 / 令牌失效 | 回退本地免费模式，提示重新连接 |
| 402 | 额度不足 / 需要开通 / 需要充值 | 打开会员页或充值页 |
| 500 | 服务端错误 | 提示稍后重试，不重复扣费 |

## 6. 计费规则（后台可配置）

### 6.1 优先级

默认顺序（后台可调）：

1. 有效余额包月 → 不限次，直接成功
2. 每日免费额度 → 消耗免费次数
3. 积分包 → 扣积分
4. 套餐 → 扣套餐双额度
5. 余额 → 扣 quota

### 6.2 余额包月

- 订购：从余额一次性扣 `monthly_price_quota`，开通 `monthly_duration_days` 天。
- 自动续费：到期自动从余额续扣；余额不足自动停止并标记续费失败。
- 退订：到期后生效，不退款，当前包月保留至到期日。

### 6.3 异常处理（服务端已内置）

| 场景 | 行为 |
| --- | --- |
| 余额不足开通包月 | 402 + `need_recharge` + 充值链接 |
| 自动续费余额不足 | 停止续费 + `renew_failed` + 应用内提醒充值 |
| 续费任务延迟 | ≤48h 按原到期日顺延；超过视为中断需重新订阅 |
| 并发重复订阅 | 事务内用户行锁，最多扣一次 |
| 重复扣费请求 | `request_id` 幂等 |
| 断网 | 客户端回退本地免费试用额度 |

## 7. 客户端 SDK 契约（最小实现）

所有客户端实现以下函数即可接入：

```js
resolveApp(settings)      // slug → app_id（自动解析并缓存）
getEntitlement(settings)  // → 统一额度明细（含 need_recharge / recharge_url）
consume(settings, count)  // → 扣费结果（携带 request_id）
subscribe(settings)       // → 开通包月（携带 request_id）
unsubscribe(settings)     // → 退订（下月生效）
```

规则：

- 打开应用调用一次 `getEntitlement` 渲染状态。
- 每次计费操作调用 `consume`，`request_id = crypto.randomUUID()`。
- `consume` 返回 `requires_upgrade` → 打开会员页；`need_recharge` → 打开 `recharge_url`。
- 包月有效期内 `consume` 直接成功（`source=plugin_monthly`）。
- 未连接 AjkAPI 时使用本地免费额度（示例：HUnit 10 次/天、净读 3 篇/天、HConvert 3 次/天、礼通 20 条/天）。

### 游戏接入说明

- “局 / 次 / 关卡” → `call_count`。
- “体力 / 金币 / 道具消耗” → `token_count`（0 时按后台“1 次=N token”折算）。
- 会员月卡 → `app-subscribe`；赛季通行证同理复用包月，天数为 30。

## 8. 各类应用接入要点

| 类型 | 技术要点 |
| --- | --- |
| 浏览器扩展（MV3） | 后台 Service Worker 发起计费请求；`chrome.storage` 存设置；manifest 需 `storage` 权限 |
| 桌面 Web（本地服务器） | 本地 Node 服务加同源代理 `/ajkapi-proxy/*` 转发到 AjkAPI，规避浏览器跨域 |
| Electron / Tauri | 渲染进程走主进程代理或允许 `file://`（`null` 来源）调用接口 |
| 移动端 / 游戏 | 直接 HTTP 调用即可；服务器已允许 Chrome 扩展来源与配置过的 Web 来源 |

## 9. 发布规范

### 9.1 代码混淆

浏览器扩展/前端必须混淆后再发布（示例：esbuild + javascript-obfuscator）。

### 9.2 发布包

| 包 | 内容 |
| --- | --- |
| `{app}-v{version}-chromium.zip` | 构建产物（dist）+ manifest + icons，可直接加载到浏览器 |
| `{app}-v{version}-src.zip` | 源码（src/scripts/package），不含 node_modules |
| `SHA256SUMS.txt` | 每个发布包的 SHA256 校验和 |

### 9.3 双仓库 + Release

- Gitee：`https://gitee.com/{user}/{repo}`，代码 + `release/` 发布包。
- GitHub：代码推送 + GitHub Release 资产（网络受限时可用 API 上传资产）。
- 广场 `runtime_config` 下载地址：
  - `download_url_gitee`：Gitee raw 或仓库归档
  - `download_url_github`：GitHub Release 资产地址

### 9.4 广场更新

发版后同步：`version`、`changelog`、`runtime_config` 下载地址、`icon`/`screenshots`。

## 10. 测试与验收清单

```text
□ 应用解析：GET /api/marketplace/apps/{slug} 返回 app_id
□ 额度明细：app-quota 返回 balance/free/monthly/renew_failed/need_recharge/recharge_url
□ 免费扣费：consume 成功且 source=free
□ 开通包月：app-subscribe 只扣一次；重复 request_id 不重复扣
□ 退订：app-unsubscribe 返回 cancelled，到期后不再扣费
□ 自动续费：到期自动续扣，余额不足时 renew_failed=true
□ 断网回退：离线时本地免费额度可用
□ 真实 UI 测试：连接、会员面板、充值提醒截图
□ 发布：混淆包 + 校验和 + Gitee/GitHub 链接可下载
```
