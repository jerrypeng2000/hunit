# AjkAPI 应用开发接口文档（统一标准 v2.0）

> 适用范围：AI 应用广场上的插件、浏览器扩展、桌面应用、移动应用、游戏。
> 定位：这是所有新应用开发的唯一接口标准。注册、认证、计费、发布、验收都按本文档执行。
> 示例应用：HUnit、CleanRead 净读、HConvert、LiTong 礼通。

---

## 1. 标准目标与治理

### 1.1 目标

- 一个应用只实现一套客户端契约，即可接入广场、额度与计费。
- 计费方式、价格、免费额度全部在 AjkAPI 后台配置，客户端不写死金额。
- 所有异常（重复扣费、并发、余额不足、续费失败、断网）由服务端和参考 SDK 统一处理。

### 1.2 版本策略

- 本文档主版本 `v2`。破坏性变更升级主版本；新增可选字段保持向后兼容。
- 客户端必须以 `request_id` 实现幂等，并对未知响应字段保持宽容。
- 服务端接口遵循「只增不改」：新增字段不动旧字段语义。

### 1.3 新应用脚手架

每次新建应用必须复制标准文档到应用目录。仓库提供脚手架：

```bash
python D:/project/ajkapi/tools/new_app.py --slug your-app --name "你的应用"
```

脚手架会自动生成并复制：

```text
your-app/
  README.md
  .gitignore
  docs/
    应用开发接口文档.md
    计费接口标准.md
  src/
    ajkapi-sdk.js
  release/
  scripts/
```

不要手写一遍又一遍的计费逻辑；复制并复用 `src/ajkapi-sdk.js`。

## 2. 应用生命周期

```text
创建应用 -> 配置计费 -> 客户端开发 -> 提交审核 -> 上架 -> 发版 -> 运营/下架
```

| 阶段 | 操作 | 结果 |
| --- | --- | --- |
| 创建 | 后台创建应用，生成唯一 `slug` | 未上架 |
| 配置 | 配置免费额度、包月、积分、套餐、模型系数 | 计费生效 |
| 开发 | 按本文档实现 SDK | 可联调 |
| 审核 | 管理员审核应用与定价 | `review_status=approved` |
| 上架 | 设置 `enabled=true`，填写图标/截图/下载地址 | 广场可见 |
| 发版 | 更新 `version`、`changelog`、`runtime_config` | 用户可下载 |
| 运营 | 监控额度接口与续费任务 | 持续稳定 |

## 3. 认证与授权

### 3.1 应用客户端

应用内使用用户令牌：

```http
Authorization: <AccessToken 或 API Token（sk-xxx）>
Content-Type: application/json
```

规则：

- 令牌由用户在 AjkAPI 控制台获取，在应用「设置」里填写。
- 令牌无效返回 `401`/`403`，客户端回退本地免费模式并提示重新连接。
- 应用客户端只访问计费接口，不访问广场安装/评价等 Web 接口。

### 3.2 服务间调用

智控后台、运维脚本使用：

```http
X-Service-Key: <billing.service_key>
```

### 3.3 管理后台

管理接口需要管理员会话：

- 登录后携带 `Ajk-Api-User: <uid>`。
- 写操作携带 CSRF Token。

## 4. 通用约定

### 4.1 基础地址

- 生产：`https://ajkapi.9zos.com`
- 所有接口前缀：`/api`

### 4.2 响应包络

```json
{
  "success": true,
  "message": "",
  "data": {}
}
```

- 业务成功但无数据时 `data` 可为 `null` 或空对象。
- 业务失败时 `success=false`，`message` 提供用户可读文案。

### 4.3 分页

列表接口统一使用：

```text
p=1&page_size=20
```

响应含 `total`、`page`、`page_size`。

### 4.4 时间与金额

- 时间戳为 Unix 秒（`int64`）。
- `quota` 为平台额度单位；`yuan` 为人民币展示价，两者分别维护。

### 4.5 幂等

- 扣费与订购必须携带 `request_id`。
- 相同 `request_id` 只生效一次，重复请求直接返回成功。
- 客户端使用 `crypto.randomUUID()` 生成。

### 4.6 错误码

| HTTP | 含义 | 客户端行为 |
| --- | --- | --- |
| 200 | 成功（含幂等返回） | 继续 |
| 400 | 参数错误 | 提示错误 |
| 401 / 403 | 未认证 / 令牌失效 / 越权 | 回退本地免费模式，提示重新连接 |
| 402 | 额度不足 / 需要开通 / 需要充值 | 打开会员页或充值页 |
| 500 | 服务端错误 | 提示稍后重试，不重复扣费 |

## 5. 广场公开接口

这些接口供广场列表、详情页和客户端自动解析 `slug` 使用。

### 5.1 应用列表

```http
GET /api/marketplace/apps?p=1&page_size=20&category=code&tag=llm&sort=popular
```

参数：

| 参数 | 说明 |
| --- | --- |
| `category` | 分类 |
| `tag` | 标签 |
| `sort` | `popular`(默认) / `newest` / `rating` / `downloads` / `name` |
| `keyword` | 关键词 |
| `plugin_type` | 插件类型，如 `tool` / `mcp_server` |
| `min_rating` | 最低评分 |

响应：`data.items`、`data.total`、`data.page`、`data.page_size`。

### 5.2 应用详情

```http
GET /api/marketplace/apps/{slug}
```

响应：

```json
{
  "data": {
    "app": {},
    "versions": [],
    "pricing": {}
  }
}
```

客户端用 `data.app.id` 自动解析 `app_id`，并缓存到本地设置。

### 5.3 分类与定价

```http
GET /api/marketplace/categories
GET /api/marketplace/apps/{id}/pricing
```

### 5.4 评价列表

```http
GET /api/marketplace/apps/{id}/ratings?p=1&page_size=10
```

响应含 `items`、`total`、`distribution`。

## 6. 广场用户接口（Web 端，非应用客户端）

安装、评价、配置更新由广场 Web 使用，走用户会话与 CSRF，不是应用客户端 SDK。

```text
POST   /api/marketplace/apps/{id}/install
DELETE /api/marketplace/apps/{id}/install
GET    /api/marketplace/installed
PUT    /api/marketplace/installed/{id}/config
POST   /api/marketplace/apps/{id}/ratings
GET    /api/marketplace/apps/{id}/ratings/mine
DELETE /api/marketplace/ratings/{id}
GET    /api/marketplace/apps/{id}/download
```

下载接口返回：

```json
{
  "download_url": "",
  "download_url_gitee": "",
  "download_url_github": "",
  "app_slug": "",
  "app_name": "",
  "version": ""
}
```

## 7. 应用客户端计费接口

应用客户端只需对接这 4 个接口。

### 7.1 查询额度

```http
GET /api/billing/app-quota?app_id={appId}
```

响应 `data.detail` 字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `balance_remaining` | int | 剩余余额 quota |
| `free_enabled` / `free_daily_quota` | bool/int | 每日免费开关与次数 |
| `free_used_today` / `free_remaining_today` | int | 今日已用/剩余 |
| `plugin_monthly_active` | bool | 是否有有效包月 |
| `plugin_monthly_start_at` / `plugin_monthly_end_at` | int64 | 包月起止时间 |
| `plugin_monthly_cancelled` | bool | 是否已退订（到期失效） |
| `auto_renew` | bool | 是否自动续费 |
| `monthly_price_quota` / `monthly_price_yuan` | int/float | 包月价格（quota / 元） |
| `monthly_duration_days` | int | 包月天数 |
| `renew_failed` / `renew_failed_at` | bool/int64 | 上次自动续费是否失败 |
| `need_recharge` | bool | 余额不足，需要充值 |
| `recharge_url` | string | 充值页地址 |
| `credits_remaining` | int | 剩余积分 |
| `call_remaining` / `token_remaining` | int | 套餐剩余 |
| `local` | bool | 客户端本地回退模式 |

### 7.2 计费扣减

```http
POST /api/billing/consume
```

请求：

```json
{
  "app_id": 19,
  "call_count": 1,
  "token_count": 0,
  "model_name": "",
  "request_id": "uuid"
}
```

规则：

- `call_count`：操作次数；`token_count`：token 消耗，为 0 时按后台「1 次=N token」折算。
- 成功 200；额度不足 402。

### 7.3 订购包月

```http
POST /api/billing/app-subscribe
```

```json
{ "app_id": 19, "request_id": "uuid" }
```

从余额扣除 `monthly_price_quota`，开通 `monthly_duration_days` 天。已有有效包月时幂等返回。

### 7.4 退订包月

```http
POST /api/billing/app-unsubscribe
```

```json
{ "app_id": 19 }
```

到期后生效，不退款；当前包月保留至到期日。

### 7.5 续费检查（运维/服务间）

```http
POST /api/billing/plugin-renew-check
```

认证：`X-Service-Key`。返回 `renewed`、`stopped`。

## 8. 管理接口（应用注册与配置）

由后台管理，需要管理员会话与 CSRF。客户端不调用。

### 8.1 应用 CRUD

```text
GET    /api/apps
GET    /api/apps/{id}
POST   /api/apps
PUT    /api/apps/{id}
DELETE /api/apps/{id}
```

### 8.2 计费配置

```text
GET /api/apps/{id}/billing-config
PUT /api/apps/{id}/billing-config
```

可配置字段：

| 字段 | 说明 |
| --- | --- |
| `balance_enabled` / `subscription_enabled` / `credits_plan_enabled` | 余额 / 套餐 / 积分包开关 |
| `priority` / `fallback_strategy` | 优先级与兜底策略 |
| `billing_mode` | `per_token` / `per_call` / `fixed_subscription` |
| `per_call_quota` | 1 次=N token |
| `subscription_token_coefficient` | 套餐 token 系数（必须 >=1） |
| `token_per_credit` | 1 积分=N token（必须 >0） |
| `free_enabled` / `free_daily_quota` | 每日免费开关与次数 |
| `monthly_price_quota` / `monthly_price_yuan` | 包月价格（quota/元） |
| `monthly_duration_days` | 包月天数（>0） |
| `auto_renew` | 到期自动续费开关 |
| `default_model` | 默认模型 |

### 8.3 模型消耗系数

```text
GET    /api/apps/{id}/models
POST   /api/apps/{id}/models
PUT    /api/apps/models/{id}
DELETE /api/apps/models/{id}
PUT    /api/apps/{id}/models/batch-coefficient
```

系数必须 `>=1.0`（盈利保护）。

### 8.4 审核与定价审批

```text
GET  /api/admin/marketplace/plugins/pending
POST /api/admin/marketplace/plugins/{id}/approve
POST /api/admin/marketplace/plugins/{id}/reject
POST /api/admin/marketplace/plugins/{id}/suspend
POST /api/admin/marketplace/plugins/{id}/restore
POST /api/admin/marketplace/pricings/{id}/approve
POST /api/admin/marketplace/pricings/{id}/reject
```

## 9. 计费模型与规则

### 9.1 计费方式优先级

```text
1. 有效余额包月（不限次）
2. 每日免费额度
3. 积分包
4. 套餐
5. 余额
```

任一方式整体覆盖本次费用即成功；全部不足返回 402。

### 9.2 余额包月

- 订购：余额一次性扣 `monthly_price_quota`，开通 `monthly_duration_days` 天。
- 自动续费：到期自动续扣；余额不足自动停止并标记 `renew_failed`。
- 退订：到期后生效，不退款，当前包月保留至到期日。

### 9.3 异常处理（服务端内置）

| 场景 | 行为 |
| --- | --- |
| 余额不足开通包月 | 402 + `need_recharge` + 充值链接 |
| 自动续费余额不足 | 停止续费 + `renew_failed` + 应用内提醒充值 |
| 续费任务延迟 | <=48h 按原到期日顺延；超过视为中断需重新订阅 |
| 并发重复订阅 | 事务内用户行锁，最多扣一次 |
| 重复扣费请求 | `request_id` 幂等 |
| 断网 | 客户端回退本地免费额度 |

## 10. 客户端 SDK 契约与参考实现

### 10.1 契约

```js
resolveApp(settings)      // slug -> app_id，自动解析并缓存
getEntitlement(settings)  // -> 统一额度明细
consume(settings, count)  // -> 扣费结果
subscribe(settings)       // -> 开通包月
unsubscribe(settings)     // -> 退订
```

### 10.2 参考实现

参考实现见 [sdk-template.js](./sdk-template.js)。新应用直接复制到 `src/ajkapi-sdk.js` 使用。

### 10.3 行为要求

- 打开应用调用一次 `getEntitlement`。
- 每次计费操作调用 `consume`，传 `request_id`。
- `requires_upgrade` -> 会员页；`need_recharge` -> 打开 `recharge_url`。
- 包月期内 `consume` 直接成功。
- 未连接时使用本地免费额度。

### 10.4 游戏映射

- 局 / 次 / 关卡 -> `call_count`
- 体力 / 金币 / 道具 -> `token_count`
- 月卡 / 赛季通行证 -> `app-subscribe`

## 11. 各类客户端接入要点

| 类型 | 技术要点 |
| --- | --- |
| 浏览器扩展 MV3 | 由 Service Worker 发起请求；`chrome.storage` 存设置；manifest 含 `storage` |
| 桌面 Web 本地服务器 | 本地 Node 加同源代理 `/ajkapi-proxy/*` 转发，规避跨域 |
| Electron / Tauri | 主进程代理，或允许 `file://`（`null` 来源） |
| 移动端 / 游戏 | 直接 HTTP 调用；服务器已放行扩展来源与配置过的 Web 来源 |

## 12. 发布规范

### 12.1 混淆

前端/扩展发布前必须混淆：esbuild + javascript-obfuscator。

### 12.2 发布包

| 包 | 内容 |
| --- | --- |
| `{app}-v{version}-chromium.zip` | 构建产物 + manifest + icons |
| `{app}-v{version}-src.zip` | 源码（src/scripts/package），不含 node_modules |
| `SHA256SUMS.txt` | 校验和 |

### 12.3 双仓库与 Release

- Gitee 代码 + `release/`；GitHub 代码 + Release 资产。
- 广场 `runtime_config`：
  - `download_url_gitee`
  - `download_url_github`

### 12.4 广场图片

- `icon`：列表缩略图 1 张，640×360 左右，<50KB。
- `screenshots`：详情页至少 3 张，同尺寸规格。

## 14. 安全与运营

- 令牌不写死、不进 Git；通过环境变量或本地存储注入。
- 客户端对 `recharge_url` 使用 `window.open` 前校验为 `http(s)` 地址。
- 服务端记录消费流水；`request_id` 全局幂等。
- 续费任务每 10 分钟运行；失败会落库供对账。
- 管理员配置系数与价格时受盈利保护校验。
